# Hikki

Notion-like local-first note app. Tauri 2 + React 19 + BlockNote + shadcn/ui + Jotai; Rust owns all I/O.

## Commands

- `pnpm dev` — Vite dev server (browser mode uses in-memory backend)
- `pnpm tauri dev` — full desktop app
- `pnpm test` / `pnpm test:watch` — Vitest (jsdom)
- `cargo test --manifest-path src-tauri/Cargo.toml` — Rust tests
- `pnpm e2e` — Playwright against Vite dev server (MemoryBackend)
- `pnpm lint` / `pnpm fmt` — oxlint / oxfmt (also run by husky on commit)
- `pnpm exec tsc --noEmit` — typecheck

## Architecture

- **Storage (hybrid local-first):** vault dir (default `~/Hikki`) holds `documents/<uuid>/document.json` + `assets/`; source of truth, iCloud-syncable. Derived SQLite FTS5 index in app-data (`index.db`) — rebuildable, never synced; the `activity` table (dashboard word-count/streak history, see the Dashboard bullet) is the one exception — it has no vault-side source of truth, so deleting `index.db` or moving vaults between machines permanently loses it. See `docs/superpowers/specs/2026-07-18-hikki-design.md`.
- **Rust** (`src-tauri/src/`): `vault.rs` (settings/layout), `document.rs` (fs CRUD, soft delete), `index.rs` (FTS5 search/reconcile), `asset.rs` (asset import + `hikki-asset://` URL resolution, traversal-checked), `fsx.rs` (atomic temp+rename writes), `history.rs` (snapshots), `commands.rs` (`*_impl` testable core + `#[tauri::command]` wrappers), `error.rs` (`HK-XXXX` codes, serialized as `{code, message}`).
- **Assets:** imported via `import_asset` command into `documents/<uuid>/assets/`, served by the custom `hikki-asset://` protocol (vault-scoped, UUID + single-component filename validation). Frontend builds URLs with `backend.assetUrl()` and `#lib/asset-url`.
- **Editor:** BlockNote (`#components/editor`) inside `src/pages/document-page.tsx`; block changes flow through the same debounced `save_document` autosave as the title. jsdom can't render BlockNote — unit tests mock `#components/editor`; real editor behavior is covered by Playwright. Re-skinned via the `shadCNComponents`/`theme` props (wired to our own `Button`/`Tooltip`/`Popover` and `next-themes`' `resolvedTheme`) plus a retargeted `--bn-colors-*` variable layer in the `.bn-root` block of `src/assets/globals.css` (`!important`-forced — `@blocknote/shadcn` ships an equal-specificity `.bn-root` rule that loads after ours); `.bn-editor{padding-inline:0; background-color:transparent}` lets our own wrapper own horizontal spacing, and `.bn-trailing-block{min-height:240px}` widens the click-to-continue-typing zone below the last block. Code blocks are shiki-highlighted (plain `shiki` package, ~26 languages, `min-light`/`min-dark` themes) with best-effort paste language detection (`#lib/guess-language`) and a copy-to-clipboard overlay (`src/components/code-block-copy-overlay.tsx`, a DOM-sibling of `BlockNoteView` — ProseMirror reverts DOM writes made directly inside its contentEditable tree). The custom `chooseVerticalPlacement` floating-ui middleware in `editor.tsx` fixes the "/" suggestion menu compressing instead of flipping upward near the viewport bottom (a feedback loop between `size()` and `autoPlacement`).
- **Comments:** `VaultThreadStore` (`#lib/vault-thread-store`) implements BlockNote's open-source `ThreadStore` abstract class, backed by `Doc.threads: unknown` (mirrors the opaque `Doc.blocks` pattern; Rust never interprets it, see `src-tauri/src/document.rs`); wired into the editor via `CommentsExtension` in `#components/editor`. Rendered as a right-side rail: `src/components/comment-threads-sidebar.tsx` mounts inside `<BlockNoteView>` (to read `BlockNoteContext`/`ComponentsContext`) but portals its painted output via `ReactDOM.createPortal` into the shared `page-rail` container that `src/pages/document-page.tsx` renders alongside the reading column (visible at `2xl` and up).
- **Table of contents:** `src/components/table-of-contents.tsx` (`react-fluid-toc`) derives heading items from `editor.document` rather than DOM-scanning (BlockNote headings are plain `div`s, not semantic `<h1>`-`<h6>`), stacked in the same `page-rail` container above the comments rail. `src/components/heading-anchor-overlay.tsx` renders real anchor elements (same DOM-sibling-overlay pattern as the code-block copy button) since setting `.id` directly on BlockNote's heading DOM gets reverted by ProseMirror's own DOM-integrity observer.
- **Theming:** `next-themes` (`#components/theme-provider`, `attribute="class"`, `storageKey="hikki-theme"`) drives light/dark across the app, including native window-chrome sync via `getCurrentWindow().setTheme()`; toggled from the Appearance control inside Settings → General (see below) — there is no separate quick-toggle button in the title bar. Base UI-backed `Tooltip`/`Popover`/`DropdownMenu` primitives (`src/components/ui/{tooltip,popover,dropdown-menu}.tsx`, built on `@base-ui/react`) are softened to match; `TooltipTrigger`/`PopoverTrigger` bridge a Radix-style `asChild` prop onto Base UI's own `render` prop, since BlockNote's bundled toolbar/badge/link buttons pass `asChild` and would otherwise render as nested `<button>`s.
- **Emoji picker:** `frimousse`'s `EmojiPicker` primitive, re-skinned as a shadcn/ui-style wrapper (`src/components/ui/emoji-picker.tsx`, matching this app's other `ui/*` component conventions) and used from `page-header.tsx`; resolves its emoji dataset from frimousse's own default `cdn.jsdelivr.net` URL, no self-hosting.
- **Frontend backend layer:** components use only `backend` from `#lib/backend/index` — `TauriBackend` (IPC) in Tauri, `MemoryBackend` in plain browsers (dev + Playwright). Never call `invoke` outside `src/lib/backend/` for this app's own custom commands — but official Tauri plugin JS SDKs (`@tauri-apps/plugin-http`'s `fetch`, `@tauri-apps/plugin-dialog`'s `open`/`save`, `@tauri-apps/plugin-opener`'s `revealItemInDir`, `@tauri-apps/api/app`'s `getVersion`) are called directly at their use site instead, never funneled through `Backend`.
- **Sidebar:** document tree metadata served from SQLite `documents` table via `Index::list_metas`; frontend renders the tree view in the left sidebar, supports collapse/expand, delete via dropdown, and hierarchical nesting via `parentId` (drag-to-reorder arrives in a later phase).
- **State:** Jotai (`#lib/store`), doc tree built by pure `buildTree` (`#lib/tree`).
- **Routing:** `createHashRouter` — `/` dashboard, `/doc/:id` editor; `AppShell` owns the macOS titlebar (drag region + traffic-light inset via `useTrafficLightInset`). `src-tauri/tauri.conf.json` sets `transparent: false`/`dragDropEnabled: false` — a transparent window conflicted with the titlebar drag region.
- **Page header:** `src/components/page-header.tsx` — full-width cover image (container-query technique, `w-[100cqw]`/`@container`) and a last-updated timestamp (`date-fns`' `formatDistanceToNow`).
- **Dashboard:** the `/` index route (`src/pages/dashboard-page.tsx`, registered as `{ index: true }` in `main.tsx`, also reachable via `sidebar-left.tsx`'s `nav-dashboard`); a `useEffect` fires `refreshDashboardAtom` (`#lib/store`), which fans out to `backend.getDashboardStats()` + `backend.getRecentDocuments(8)` and fills `dashboardStatsAtom`/`recentDocsAtom` — a rejected load reports `HK-7001` and renders a zeroed `EMPTY_STATS` instead of crashing. Five presentational components: `dashboard-greeting.tsx` (time-of-day greeting + New document button, reusing the sidebar's own `refreshDocsAtom`), `dashboard-stat-tiles.tsx` (documents / words / day streak / edited-this-week), `dashboard-activity-chart.tsx` (recharts `AreaChart` over the 30-day `dailyWords` series), `dashboard-heatmap.tsx` (35 days = exactly 5 weeks, so a plain `grid-cols-7` needs no leading blanks; shades via `#lib/activity-level`'s `bucketActivityLevel`/`ActivityLevel`), and `dashboard-recent-list.tsx`. Server-side, `commands.rs`' `create_document_impl`/`save_document_impl` append one `activity` row per create/debounced-autosave via `record_activity` (`word_delta` is signed — a shrinking edit records a negative delta), and `index.rs`'s `dashboard_stats(utc_offset_minutes)` buckets those rows by the _caller's local_ calendar day in plain Rust rather than SQLite's UTC-based `date()`, delegating to a private `now`-parametrized `dashboard_stats_at` so day-boundary tests pin an exact instant instead of racing the wall clock. The 30/35-day series come from a 45-day-windowed query, but `streak_days` deliberately runs a second, _unbounded_ query so a longer-than-45-day streak isn't silently capped. `MemoryBackend.getDashboardStats()` is an independent reimplementation of the same rules and must stay behaviorally identical.
- **Version history:** `history.rs` writes rolling snapshots to `documents/<uuid>/history/` on save (10-min coalescing, 50 kept); history UI arrives in Phase 6.
- **AI Writing Tools:** `src/lib/ai/models.ts`'s `getAiModels()` builds a lazily-cached `@earendil-works/pi-ai` `Models` collection, split real-vs-faux via `isTauri()`: the real Tauri app registers `openaiProvider()`/`anthropicProvider()` under the literal ids `"openai"`/`"anthropic"`; the Vite dev server and Playwright e2e (both plain-browser, never inside Tauri) instead get a single scripted `fauxProvider()` registered as `"faux"`, so no real, billed API calls ever happen outside the desktop app. `prompts.ts`'s `WritingToolAction` union (`proofread`/`rewrite`/`tone`/`transform`/`compose`/`custom`) maps to a per-action system prompt plus user-message shape (`buildContext`), and `client.ts`'s `streamWritingTool` async generator resolves the model from the _combined_ catalog (a provider-scoped lookup would miss the faux provider's `"faux"`-registered models), fetches that provider's API key over IPC, and yields `delta`/`done`/`error` events consumed by the popover below. API keys never touch the plain settings file: `src-tauri/src/ai.rs`'s `get_api_key_impl`/`set_api_key_impl`/`delete_api_key_impl` read/write only the OS Keychain (via the `keyring` crate, service `com.hikki.app.ai`) — the default provider/model picked in AI Settings persists separately, in the ordinary `AppSettings` file, via `save_ai_settings`/`get_ai_settings`. `src/main.tsx` replaces `window.fetch` with `@tauri-apps/plugin-http`'s `fetch` under `isTauri()`, since OpenAI/Anthropic's APIs don't send the CORS headers a webview's native `fetch` requires; `src-tauri/capabilities/default.json` scopes the corresponding `http:default` permission to just `https://api.openai.com/*` and `https://api.anthropic.com/*`, not an open allow-all. The feature surfaces via a Writing Tools button (`src/components/writing-tools-button.tsx`) appended to the formatting toolbar's item list in `#components/editor`'s `FormattingToolbarController`, also reachable as `⌘J` while there's a live text selection; both open `src/components/writing-tools-popover.tsx`, which offers Proofread/Rewrite, tone chips (friendly/professional/concise), transforms (summary/key points/list/table), a free-text "describe your change" input, and Compose, streams the response into a preview pane, then commits via Replace/Insert below (both through BlockNote's own `editor.replaceBlocks`/`editor.insertBlocks` — never raw `Doc.blocks` mutation) or discards it; every failure path in `runAction` (missing defaults, a stream `error` event, or the surrounding `try`'s own catch) reports through `HK-3005` (see the Settings/errors/logging bullet below), not a local-only error. Per-provider API key save/test-connection plus a default-provider/model picker now live in `src/components/settings/ai-section.tsx` (Settings → AI), not a standalone dialog — Phase 3's original `ai-settings-dialog.tsx` was a deliberately minimal pull-forward, folded into the real Settings shell once Phase 4 built it.
- **Settings, errors, and logging:** `src/components/settings-dialog.tsx`'s `SettingsDialog` is a sidebar-nav-inside-a-wide-`Dialog` (General/AI/Logs/About & Updates, `src/components/settings/*-section.tsx`), opened via a gear button in `sidebar-left.tsx`'s `SidebarFooter` (`data-testid="settings-trigger"`, replacing Phase 3's standalone AI-settings trigger) or the `⌘,`/`Ctrl+,` shortcut (a `keydown` listener alongside that same button, not in `title-bar.tsx` — the title bar only renders the sidebar-collapse trigger now); it reads/writes `settingsDialogOpenAtom`/`settingsDialogSectionAtom`/`openSettingsAtom` (`#lib/store`) directly, no props. Appearance has no separate nav entry — it's the first control inside General: a pill-shaped light/dark/system switcher (sr-only radio inputs + `peer-checked`-styled `<label>`s, `data-testid` on the label since that's the actual click target — label-click delegation to the associated radio is native browser/jsdom/Playwright behavior) driving `next-themes` directly (see the Theming bullet above); the multi-preset color/radius gallery from the original design spec was deprioritized separately. About is a static `getVersion()` display — called unconditionally rather than gated behind `isTauri()` (which would also make it untestable, since jsdom never sets `window.__TAURI_INTERNALS__`), with `"dev"` as the initial/fallback state since `getVersion()`'s IPC call rejects outside a real Tauri webview and the rejection is simply swallowed. General also offers the vault path (`backend.getVaultInfo`/`setVaultPath`, native folder picker via `@tauri-apps/plugin-dialog`'s `open`), a rebuild-index button, and (where `@tauri-apps/plugin-opener` is already wired) a reveal-in-Finder button. `src/lib/errors.ts`'s `reportError(code: HkErrorCode, context?)` is the single funnel for every user-facing failure: it looks up a fixed `{message, severity, openSettings?}` from `ERROR_DEFINITIONS` (16 codes today, grouped `HK-1xxx` vault/fs, `HK-2xxx` index, `HK-3xxx` AI, `HK-6xxx` Settings/Logs, `HK-9xxx` unexpected), fires the matching `sonner` toast (with an "Open Settings" action when `openSettings` names a section, written via `jotai`'s `getDefaultStore().set(...)` — this app's only atom write from outside a React component), and always logs a structured entry via `src/lib/logger.ts`'s `log.error(...)`. `src/components/error-boundary.tsx`'s app-wide `ErrorBoundary` (wraps the whole router in `main.tsx`) and a `window.onunhandledrejection` listener both feed the same funnel under `HK-9001`; this is a different, broader boundary than the pre-existing `src/components/editor-boundary.tsx`, which only catches malformed-document rendering failures. Logs persist as JSONL at `app_data_dir/logs/hikki.log` (`src-tauri/src/logging.rs`, 5MB size-based rotation, 5 rotated files kept) via `append_log`/`read_logs`/`clear_logs`/`export_logs` (`Backend`, `#lib/backend/index`) — `export_logs` re-runs `read_logs`'s own level/text filter server-side and writes the result via `fsx::write_atomic` to a path from `@tauri-apps/plugin-dialog`'s `save()` (which only returns a chosen path, never writes content itself — confirmed against the installed plugin's types rather than assumed), avoiding a second `@tauri-apps/plugin-fs` dependency; the Logs section (`src/components/settings/logs-section.tsx`) surfaces this as a level filter, text search, and Clear/Export buttons.

## Conventions

- TDD: failing test first (Vitest / cargo test / Playwright), then implement.
- `data-testid` on every interactive element (kept in dev, will be stripped in prod builds via `@rolldown/plugin-babel` with `react-remove-properties`; see `vite.config.ts`).
- shadcn/ui first — install missing primitives with `pnpm dlx shadcn@latest add <name>`, never hand-roll.
- Import aliases: `#components/*`, `#lib/*`, `#lib/backend/*`, `#hooks/*`, `#pages/*` (package.json `imports`).
- IPC payloads are camelCase; Rust uses `serde(rename_all = "camelCase")`.
- Conventional commits; husky runs oxlint/oxfmt — never `--no-verify`.
- Design language: soft Notion-like aesthetic per spec §14 — warm low-contrast tokens in `src/assets/globals.css`, `--radius: 0.625rem`, muted chrome, 150–200ms transitions. Match it in all new UI.
